# Db review and rework — 2026-10-11

Branch `improvements1`, after the BaseObject rework (9b6ab75). Companion changes: `src/Laf/Exception/DbConnectException.php`

## 1. Bugs found and fixed

| # | Where | Bug | Fix |
|---|---|---|---|
| 1 | `getInstance()` | `self::$instance = new Db()` was assigned before reading the settings and connecting: after a failed first call every later call returned the dead instance without throwing (`query()`/`prepare()` null, `getConnection()` null → fatals; `PhpGridTest` believed the DB was up when `BaseObjectTest` had failed first) | the instance is cached only after `connect()` succeeded |
| 2 | `getInstance()` | `getProperty('database.engine') ?? 'mysql'` never fell back (`getProperty` throws); `database.port` was required too, so `sample_files/database.php` could not connect | `fromSettings()`: hostname, database_name, username required; password, port, engine optional with defaults |
| 3 | `connect()` | only `'mysql'` and `'postgres'` were recognised; `mariadb`, `postgresql`, `pgsql` left the connection null and the next line fatalled on `setAttribute()` (an `\Error`, not an `\Exception`) | engine normalised (`normalizeEngine()`); unknown engines throw `DbConnectException` before any connection attempt |
| 4 | `connect()` | a failed connection rethrew the raw driver exception; `DbConnectException` existed but was never used; the SQL error logger path ran `SHOW TABLES` on the dead connection | `DbConnectException::fromPdo()` (extends `PDOException`, DSN without credentials in the message, driver exception as previous); no logging attempt without a connection |
| 5 | `query()` / `prepare()` / `execute()` | returned `null` / `0` silently when there was no connection; `execute()` returned `false` under `: int` | connect on demand (`getConnection()`), typed `\PDOStatement` / `int` returns, failures are the driver's `PDOException` as before |
| 6 | `handleSqlErrorLogging()` | `SHOW TABLES LIKE` (MySQL only) through the static `getOne()` on every error; a missing log table threw `\Exception('Missing sql logger table')` **replacing the original error**; a failing `storeLogEntry()` re-entered the logging path (recursion) | engine-aware `tableExists()` checked once, logger switched off with one warning (PSR logger or `error_log`), re-entrancy guard, a logging failure never reaches the caller |
| 7 | `prepare()` + `execute()` split | only the prepare was wrapped, so execution errors (the common ones) never reached the SQL error logger or the error state | `statement()` wraps prepare + bind + execute; the fetch helpers, `BaseObject` and `Query` use it |
| 8 | error state | `has_error` was never set to true; `setErrorTraceString($ex->getTrace())` stored an array in the string field (`getErrorTraceString(): string` → TypeError); `getErrorMessage(): string` / `getErrorTrace(): array` fatalled before the first error | `recordError()` sets message, trace, trace string and the flag; nullable getters; `hasError()`, `clearError()` |
| 9 | `getLogger(): LoggerInterface` | property never initialised → `Error` on every call (`AuditLog::fail()` always fell back to `error_log`); the logger, when set, was never used | `?LoggerInterface`; statements logged at debug with their time, failures at error, connection at debug/error |
| 10 | `getRowObject()` | returned `new \stdClass()` when nothing matched and declared `?\stdClass` although any class name could be passed | returns `null`, declared `?object` |
| 11 | `getRow()` | `$fetchType = 2` magic number | `\PDO::FETCH_ASSOC` |
| 12 | `getInsertId()` | `lastInsertId()` without a sequence → `lastval()` on PostgreSQL | `?string $sequence` (BaseObject uses `RETURNING` since 9b6ab75) |
| 13 | `PhpGrid::isPostgres()` | called `Db::getAttribute()`, which did not exist → always false; once it worked, the PostgreSQL branch applied `LOWER()` to integer columns (`eq` search on `age` returned nothing) | `Db::getAttribute()/setAttribute()/getDriverName()` added; `LOWER()` only on textual columns, `LIKE` on other columns casts to text |
| 14 | `convertClassNameToTableName()` | returned `_service_order` (leading underscore) | trimmed; `convertTableNameToClassName()` delegates to `Util` |

Pre-existing and kept on purpose: `ATTR_EMULATE_PREPARES = false` (routerarena binds `LIMIT :start, :limit`),
`ATTR_ORACLE_NULLS = NULL_EMPTY_STRING` ('' fetched as null; now `database.empty_string_as_null`), raw `PDOException` from
statements (apps and tests catch it), positional constructor arguments (asm `data/config.php:342` passes `(host, db, user, pass, port)`),
string ports (asm/routerarena config), the static fetch helpers (`$liveDb::getOne(...)` in asm's archive scripts).

## 2. Design

- **Instances**: `getInstance(string $name = 'default')` builds from `database.*` (or `database.<name>.*`) through
  `fromSettings($prefix)` and caches after a successful `connect()`; `setInstance()`, `hasInstance()`, `resetInstance()`
  (disconnects). Everything that used to be a private field with no setter is now configurable: charset, socket, persistent,
  connect timeout, PDO options, DSN override / extra, session time zone, PostgreSQL schema, init commands, empty-string-as-null.
- **Connection**: `connect()` (idempotent), `disconnect()`, `reconnect()`, `isConnected()`, `ping()`, `getConnection()`
  (opens on demand), `getDsn()`, `getAttribute()`, `setAttribute()`, `getEngine()`, `isMysql()`, `isPostgres()`,
  `getDriverName()`, `getServerVersion()`, `tableExists()`.
- **Statements**: `query()`, `execute()`, `prepare()` as before (typed), plus `statement($sql, $params)`: named keys with or
  without the colon, positional values, typed by PHP type or an explicit `[value, PDO::PARAM_*]` pair (`Db::binding()` is the
  one conversion rule, shared with `BaseObject`/`Query`). Every statement goes through `timed()`: last SQL, exec time, query
  count, total time, optional query log, PSR debug/error records, error state, SQL error logger.
- **Fetch helpers**: instance `fetchAssoc/fetchAllAssoc/fetchNum/fetchAllNum/fetchOne/fetchColumn/fetchPairs/fetchObject`;
  the static `getRowAssoc/getAllAssoc/getRowNum/getAllNum/getRow/getRowObject/getOne/getColumn/getPairs/run/escape` work on
  the default connection. `getOne()` keeps returning `'1'/'0'` for booleans and `null` for no row / NULL.
- **Transactions**: `beginTransaction/commit/rollBack/inTransaction`, nest-aware `transaction(callable)`.
- **Errors**: `DbConnectException` for connections (a `PDOException`, so both `catch (\PDOException)` and `catch (\Exception)`
  match), the driver's `PDOException` for statements; `hasError()`, `getErrorMessage()`, `getErrorTrace()`,
  `getErrorTraceString()`, `clearError()`.
- **Modern PHP**: typed properties, typed signatures everywhere (constructor parameters stay untyped because the apps pass
  string ports and `false`), `static` fluent setters, no 8.1+ syntax.

## 3. Compatibility

Kept: every public method name and the static helpers; `getInstance()` without arguments; positional constructor;
`getHostName/getDatabase/getUserName/getPassword/getPort` (used by asm's archive scripts); `getConnection()` for raw PDO use
(routerarena transactions, `FOR UPDATE`); `setSqlErrorLogger()` (asm `index.php`); exception classes seen by callers.

Behaviour changes to know about:
- A failed `getInstance()` throws every time (no dead cached instance).
- `query()/prepare()/execute()` never return null: they connect on demand and throw `DbConnectException` when that fails.
- `getRowObject()` returns `null` instead of an empty `stdClass` when nothing matches (no callers).
- `getErrorMessage()` and friends are nullable and `hasError()` is true after a failure (it never was before).
- A missing SQL error log table no longer throws; the logger is switched off for the connection and a warning is logged once.
- `convertClassNameToTableName('ServiceOrder')` is `service_order` (was `_service_order`; no callers).
- `PhpGrid` on PostgreSQL now really takes its PostgreSQL branch (case-insensitive text search/sort).

- Integration MariaDB 12.2 and PostgreSQL 18.3: 141 tests / 545 assertions each, including `DbTest` (binding forms, booleans
  and nulls, every fetch helper, error capture, SQL error logger with an existing / missing / failing table, PSR logger,
  driver info, query log, ping/disconnect/reconnect, transactions, second named connection, failed connection, session time

- PHPStan level 5 clean on `Db.php`, `BaseObject.php`, `Query.php`, `DbConnectException.php`; `PhpGrid.php` unchanged (one
  pre-existing finding).

## 5. Not done / next

- `Identifier::engine()` still reads `database.engine` from Settings; a second connection on a different engine would need
  the quoting to come from the connection (`Db::getEngine()`), i.e. `Identifier::quote($name, $db->getEngine())` at the call sites.
- `SimpleTable::setSql()` and the generators' metadata queries are outside this rework.
- Automatic reconnect on "server has gone away" is not attempted; `ping()` + `reconnect()` are available for long-running scripts.
